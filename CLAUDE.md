# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## О проекте

Браузерные развивающие игры для дочки 8–9 лет. Язык интерфейса всех игр — **русский**. Тексты, кнопки, инструкции, похвала — на русском, простым языком, рассчитанным на ребёнка 8–9 лет.

## Жёсткие ограничения стека

Эти правила не обсуждаются — на них держится вся архитектура:

- **Чистый HTML/CSS/JS.** Никаких фреймворков (React, Vue и т.п.), никаких сборщиков (Vite, webpack), никаких npm-зависимостей, никаких пакетных менеджеров.
- **Одна игра = один самодостаточный `.html` файл.** HTML, CSS (`<style>`) и JS (`<script>`) — всё внутри одного файла. Без отдельных `.css`/`.js`, без шрингов между играми.
- **Запуск двойным кликом, без сервера.** Файл открывается напрямую в браузере по протоколу `file://`. Сервера (`localhost`, `python -m http.server` и т.п.) нет и не будет.
- **Полностью офлайн.** Никаких CDN, внешних ссылок на шрифты/библиотеки, загрузки ресурсов из сети. Всё необходимое встроено в файл.

## Что из этого следует (ловушки `file://`)

Протокол `file://` блокирует то, что работает на сервере. Поэтому **нельзя**:

- ES-модули и `import`/`export` между файлами (`<script type="module" src=...>` → CORS-ошибка). Весь JS — инлайн в одном `<script>`.
- `fetch()` / `XMLHttpRequest` к локальным файлам (JSON, тексты). Данные (уровни, словари, вопросы) встраиваются прямо в JS как объекты/массивы.
- Web Workers из отдельных файлов.
- Картинки/звук лучше встраивать как data-URI (base64) или генерировать кодом (Canvas, Web Audio API, эмодзи, CSS), чтобы игра оставалась одним файлом.

Навигация по ссылкам (`<a href="game.html">`) работает — это переход страницы, а не запрос ресурса.

## Сборка, тесты, запуск

Шага сборки нет. Линтера и тестов нет. «Запустить» = открыть `.html` в браузере (двойной клик или `start имя_файла.html` в PowerShell). Проверка — ручная: открыть файл, пройти игру.

## iPhone / iPad

Игры используются и на iOS. На iPhone/iPad нет модели «открыть локальный файл двойным тапом» — Quick Look не выполняет JS как надо, а Safari не открывает `file://` из «Файлов». Поэтому для iOS проект **дополнительно публикуется на статический хостинг** (GitHub Pages и т.п.) и открывается по ссылке; правило «без сервера» относится к разработке/Windows, хостинг — это только доставка, игра по-прежнему вся клиентская. Локальный git-репозиторий заведён для деплоя; `.claude/` исключён через `.gitignore`, есть `.nojekyll` для GitHub Pages.

В каждой игре держать iOS-совместимость: `<meta viewport ... maximum-scale=1, user-scalable=no>`, `touch-action: manipulation` и снятый `-webkit-tap-highlight-color` на кнопках, `user-select/-webkit-touch-callout: none` (чтобы удержание пальца не открывало меню выделения), `:hover` только под `@media (hover: hover)`, один переиспользуемый `AudioContext` с `resume()` внутри жеста (iOS глушит и ограничивает их число), apple-mobile-web-app мета-теги для запуска с домашнего экрана.

## Структура (по мере появления кода)

- Корень: `index.html` — стартовое меню-лаунчер со ссылками на игры. Это единственное допустимое исключение из «всё в одном файле»: меню ссылается на игры через `<a href>`.
- Каждая игра — отдельный `*.html` в корне (или в подпапке с понятным русским/латинским именем). Имя файла отражает игру.

## Принципы под возраст 8–9 лет

При создании любой игры держать в голове:

- Крупные кликабельные элементы, крупный читаемый шрифт, высокий контраст.
- Короткие понятные инструкции; не предполагать, что ребёнок прочитает длинный текст.
- Дружелюбная обратная связь: хвалить за успех, на ошибку реагировать мягко и давать попробовать снова (без «проигрыша» и резких звуков/цветов).
- Развивающая цель у каждой игры явная (счёт, чтение, память, логика и т.п.) — отражать её в названии и в коде комментарием сверху.

**Общие механизмы (продублированы инлайн в каждой игре — общих файлов нет!):**
- **Навигация:** верхний бар `🏠 К играм` + `🎚️ Уровень`/`🔄 Заново` (в квиз-играх); экраны start→game→end; лёгкое подтверждение выхода с середины (overlay `#confirmOverlay`, функция `askConfirm`).
- **Конфетти:** `window.fireConfetti()` — отдельный `<canvas id="confetti">` + IIFE перед `</body>`. Вызывается на победе/финале.
- **Копилка звёзд:** `window.awardStars(game, n)` пишет в общий `localStorage`. Ключи: `omma_stars_total`, `omma_best_<game>`, `omma_plays_total`. Читает и показывает лаунчер («Мои награды» + бейджи).
- **Имя/герой:** `localStorage` `omma_name`, `omma_hero` (задаются в лаунчере; имя подставляется в финальную похвалу игр через `title.replace(/!$/, ', '+nm+'!')`).
- **Темы оформления:** `localStorage` `omma_theme` (`''`/`rainbow`/`flower`/`space`). Применяется через `data-theme` на `<html>` + инжект CSS (IIFE перед `</body>`). Переключатель — в лаунчере.

**Совместимость эмодзи (ВАЖНО):** использовать только эмодзи **≤ Emoji 12.0 (2019)**. Новые (E13.0+: 🪥🪞🪟🫖🫛🫐🦭🪰🪲🪿🦤🦬🪚 и т.п.) на старых iOS/Windows рисуются пустым квадратом ▢. При добавлении слов/вариантов проверять год эмодзи.

**Деплой:** `git push origin main` → GitHub Pages (`vkassu.github.io/GAMES_FOR_OMMA`). Коммитить/пушить только по просьбе. Разрешения настроены в `.claude/settings.local.json` (рутина без вопросов, опасное — спрашивает).
